## 평가 전에 고정한 입력

- [v3 질문·근거 대상](../eval/retrieval_holdout_v3.json), [메타데이터·SHA](../eval/retrieval_holdout_v3.meta.json): 양성24·범위밖24, 총48문항/24개 한·영 질문군이다. 독립 사용자48명이나 사람 인증 정답을 뜻하지 않는다.
- 양성은 가격16·비가격8문항이다. 정상 가격/결제/환승/환급 정보를 보존하면서, 비슷한 단어가 있어도 문서가 값을 제시하지 않는 질문을 구분한다.
- R6 v1/v2와 R3 공개 평가 두 세트에 같은 문장이 없음을 확인했다. 같은 코퍼스·유사 의도를 사용하므로 완전히 독립된 도메인 검증이라고 하지 않는다.
- main `f99704d`와 후보 `d83e89f`를 비교한다. 후보의 제목·변경 파일명과 이슈 논의는 읽었지만, 후보 구현·추가 메타데이터 내용·검색 출력은 읽지 않은 상태에서 질문·근거·기준을 커밋한다.
- 후보에는 코드뿐 아니라 지식 메타데이터 변경도 있다. 각 커밋의 자체 공식 코퍼스를 사용하고 양쪽 코드·지식 해시를 기록한다. 코드만 바꾼 실험으로 설명하지 않는다.

## 판정 규칙

공식 문서 MemorySearch, min_score0.25/k3/상대0.5를 양쪽에 고정한다. 새 v3는 커밋 후 각 버전에서 한 번씩 측정하며 결과를 보고 임계값·질문·근거·기준을 바꾸지 않는다.

기존 잠정 QA 조건을 유지한다: **v3 양성 top3≥90%, 범위밖 오탐0건**. 공개 R6/R3 회귀에서 이전에 통과한 양성 문항이 실패로 바뀌는지도 확인한다. 회귀/이미 알려진 질문 결과를 새 미관찰 평가와 합산하지 않는다. 검색의 빈 결과와 Agent의 근거 없는 답변 차단도 별도 지표다.

통과하더라도 QA 후보 판정이지 운영 배포·실제 모델 품질·릴리스 설치 조합의 승인이 아니다. 통과하지 못하면 실패 질문과 다음 작업을 보고하고 미완료 이슈를 완료로 닫지 않는다. 실제 LLM/임베딩·운영 DB·배포를 사용하지 않는다.
