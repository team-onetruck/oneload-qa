## 추가 검사에서 남은 문제

1. **RAG main 전체98/101, 실패3·skip0.** 위치 카드와 POI 별칭 사전은 지도2026-10-23.1에 머물러 새 Data25.2와 다르다. 정확한 POI 기대 검사도 질문8개에서 불일치한다. 첫 예는 ‘보증금 환급기’가 두 환급기 후보를 반환하는 경우다. 새 후보에서의 개선과 main을 구분한다.
2. **Agent 지도 호환 검사 exit1, 호환 E2E NOT_RUN.** Agent `mocks/maps`가 Data main 지도와 다르다. 소스를 복사해서 통과시키지 않았다. 별도의 실제 Backend API27/28/7 통과와 이 사전 검사 실패는 함께 기록한다. Agent의 기존 xfail2건은 Travel Center·도심공항터미널 문구/위치 기대 차이이며 실패나 통과로 재라벨하지 않았다.
3. **근거·인용 제어5/6.** 새 Agent main은 NO_ANSWER, 인용 없음/범위 위반 차단, 실제 인용한 출처 선택이 통과한다. 그러나 600자 이후의 `[2]`가 최종 답변에서 잘려도 출처2가 남는다. `_grounded()`가 잘라내기 전 본문에서 인용 번호를 수집하기 때문이다. [제어 결과](../reports/grounding-current-20261026.json). FakeLLM의 제어 출력 검사이며 실제 모델의 사실성 점수가 아니다.
4. **App #41 생성 계약 누락 유지.** 새 intent3개·슬롯4개·plan/steps 타입이 여전히 없다. 단위519건 통과로 이 차이가 해소되지는 않는다. [현재 계약 대조](../reports/frontend-contract-drift-20261026.json). 새 표 구매 화면 동작과 행동 계획 API 화면 구현은 구분한다.

## 환경·다음 작업

Python3.12.14·81패키지 `uv pip check` 호환, 기존 `requirements-validation.lock.txt`와 Node26.7.0/pnpm11.13.0을 사용했다. App 의존성은 frozen lock으로 오프라인 설치했다. 실제 모델·임베딩0회, QA가 만든 일회용 PostgreSQL만 사용·정리했다. 배포·운영/기존 DB·실제 휴대폰·현장 사진·사람 근거 검토·Backend에 pin된 RAG 릴리스 설치 조합은 검사하지 않았다. 원시 로그와 비밀값은 공유하지 않는다.
